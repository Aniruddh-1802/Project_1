================================================================================
🔑 KEY POINTS TO UNDERSTAND
================================================================================

1. The t / t+1 Rule (CRITICAL)
   ├─ Features use data from [t-24h, t]
   ├─ Labels describe what happens at [t+1]
   └─ Features can NEVER see data from t+1 (or accuracy is fake!)

2. Chronological Split (MANDATORY)
   ├─ Training: Earlier days
   ├─ Testing: Later days
   └─ NO random shuffling (time-series data!)

3. Not Congestion, But Attention Signal
   ├─ We predict: "Unusual activity pattern"
   ├─ We DON'T have: Capacity, throughput, latency
   └─ For humans: "Please investigate this grid"

4. All Paths Configurable
   ├─ Input paths in config.py
   ├─ Output paths in config.py
   └─ NO hardcoding anywhere

5. Designed for Integration
   ├─ FastAPI can call predict.py
   ├─ Airflow can call batch_score.py
   ├─ Claude Phase 7 uses outputs
   └─ React dashboard displays scores
